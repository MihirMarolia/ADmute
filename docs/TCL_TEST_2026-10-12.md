## Diagnostic follow-up 0.1.1

- Adds a narrow YouTube pairing rule: exact `Sponsored` + exact `Send to phone` together. Neither label alone triggers; excluded title/description/recommendation containers are ineligible. This rule cannot help if the labels are not exposed to the app.
- Empty/whitespace-only virtual labels no longer establish a complete meaningful read.
- Debug service dumps report node/empty-label counts and known marker categories; announcement events are observed for diagnosis. Events remain **diagnostic only**, never ad evidence.
- An explicit debug-only screenshot probe uses Android's screenshot API, then discards pixels and retains only brightness counts. It is **not OCR** and does not capture continuously. Its additional screenshot capability exists only in debug resources.
- A debug-only 10-second output test isolates cover/volume handling from the detector. It requires a selected foreground app and keeps normal pause, app-exit, and lifecycle recovery controls.
- OCR implementation awaits evidence that the ad labels are present in capturable frames. Do not bypass protected content or briefly hide the visual cover to inspect ads.

On Android 11 a display screenshot can include the app's dark cover. Android's API for taking an app-window screenshot underneath an accessibility overlay is available from API 34 (Android 14). This is a separate restoration constraint even if the initial ad labels can be captured.

References: [Android screenshot APIs](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService), [local OCR with ML Kit](https://developers.google.com/ml-kit/vision/text-recognition/v2/android).
