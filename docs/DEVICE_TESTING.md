# Google TV test and installation guide

## Install

Enable developer options / debugging on your own TV. Pair ADB using the pairing information shown by the TV if it uses wireless debugging, then connect to the address it displays. Do not expose debugging outside your trusted local network.

```sh
adb pair TV_ADDRESS:PAIRING_PORT
adb connect TV_ADDRESS:DEBUG_PORT
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n org.admute/.MainActivity
```

Open ADMute, select settings, and explicitly enable its accessibility service. Developer access does not replace user consent. Keep the remote nearby. Test first at low volume with someone who can safely view the uncovered screen. **Detection does not eliminate initial flashes or guarantee that every ad is recognized.**

## Acceptance matrix

Repeat for **YouTube / Tubi / Plex** with TV speakers, then your normal HDMI/CEC/soundbar route. Record app version and English UI selection. Use ad-supported content on Plex; personal-library content should not activate.

| Case | Expected result |
| --- | --- |
| 20 movie/video launches | No mute/cover during title, loading, trailer, skip intro |
| 10 minutes home/search/recommendations | No protection, even with advertising words in titles |
| Pre-roll, mid-roll, post-roll, multi-ad pod | Confirmed specific player labels trigger selected effects |
| Bare `Ad` / generic `Sponsored` alone | No detection in this conservative version |
| End of ad labels | Release after 1.5 s of complete clear samples |
| Brief inter-ad gap <1.5 s | Cover and mute remain active |
| Mute only / cover only | Only chosen effect occurs |
| Already muted before ad | Remains muted afterward |
| Set volume to a new nonzero level during ad | New level is respected; no repeated muting or baseline overwrite |
| Ten exits from original level, e.g. 12 | Exact original media stream volume restored |
| Home / app switch / disable selected app | Cover disappears and volume releases on next foreground evaluation |
| Double Back within 0.8 s | Release and pause one minute; Back still navigates normally |
| Hold a remote key / ordinary single Back | No accidental shortcut |
| Disable accessibility service during an ad | Lifecycle cleanup releases effects |
| Kill process during an ad, reconnect service | Overlay disappears; saved zero volume recovered on reconnect |
| Incomplete same-app tree | UNKNOWN grace bounded to 8 s after last AD |
| Missing active tree | Immediate release |
| Continuous stuck positive label | Release at 3 minutes; no re-trigger until stable clear |
| Fixed media volume / external speaker ignores stream writes | Do not claim successful audio muting; assess cover separately |
| Regular flashing movie scene | No intervention: scope is recognized ads only |

## Detection investigation

After playback, open **Detection check** in ADMute. It shows the last selected-app package, visible label count, whether traversal completed, and the evidence category. These are diagnostic counts, not a real-time indicator once you leave the app. A complete tree may still omit visually rendered video labels.

For development only, you can inspect a tree using ADB:

```sh
adb shell uiautomator dump /sdcard/admute-window.xml
adb pull /sdcard/admute-window.xml
```

These developer-created dumps may contain private titles/account details; keep them local and remove them from the TV afterward. They are not generated by ADMute. Some players expose no useful text and a dump cannot fix that. Record observed label wording, class, ancestor IDs, and package before changing a rule. Do not guess from screenshots alone. Never commit private dumps.

## Explicit debug diagnostics

Debug builds provide these commands while a selected app is foregrounded:

```sh
adb shell dumpsys activity service org.admute/.AdAccessibilityService
adb shell dumpsys activity service org.admute/.AdAccessibilityService screenshot-probe
adb shell run-as org.admute cat shared_prefs/comfort.xml
adb shell dumpsys activity service org.admute/.AdAccessibilityService comfort-test
```

The first command reports only counts and known ad-marker categories, including recent announcement events. Events are diagnostic only. `screenshot-probe` requests one screenshot using the accessibility API (Android 11+ in a debug build), then discards it; only brightness counts/error status are retained in `probeSummary`. The probe is not OCR.

`comfort-test` explicitly arms a 10-second mute/cover test using current preferences in the selected foreground app. It is a device-output test, not a detection result. It releases on timeout, app exit, pause, service stop, or double Back. Already-muted audio remains muted; avoid changing the volume unless intentionally testing user overrides. None of these commands grant accessibility permissions or bypass protected content.
